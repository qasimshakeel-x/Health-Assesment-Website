# API Spec — AI Longevity Intelligence Platform

All endpoints under `/api/v1`. OpenAPI 3.1 docs auto-generated by FastAPI at `/docs` (Swagger) and
`/redoc`. Auth model: see `03-AUTH.md`.

## 1. Auth
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/auth/register` | No | Create account |
| POST | `/auth/login` | No | Returns `access_token` + `refresh_token` |
| POST | `/auth/refresh` | Refresh token | Rotates refresh token, issues new access token |
| POST | `/auth/logout` | Yes | Revokes current refresh token |

## 2. Assessment Pipeline
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/predict` | Yes | Submit health profile (+ any enabled screening_responses), runs full ML pipeline across the active `DISEASE_REGISTRY` |
| GET | `/predict/{userId}/latest` | Yes | Latest prediction + all `disease_risk_results` rows |
| GET | `/predict/{userId}/history` | Yes | *(new)* List of past predictions, paginated — useful once users retake the assessment over time |
| GET | `/shap/{predictionId}` | Yes | SHAP rows for a prediction, optionally filtered `?disease=stroke` |
| GET | `/simulate` | Yes | Future health simulation, query params for lifestyle deltas + horizon |

## 3. Diseases / Screening Metadata *(new, needed once diseases are phased in)*
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| GET | `/diseases` | Yes | Returns the currently active `DISEASE_REGISTRY` entries (key, category, label, whether it needs extra screening questions) — lets the frontend render the right form fields per rollout phase without a redeploy |
| GET | `/screenings/{screeningKey}/questions` | Yes | Returns the question set for a given screener (gad7, sleep_apnea, pcos, anemia, burnout, thyroid) so the form can be built dynamically |

## 4. Diet Chat
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/chat/{userId}/message` | Yes | Send a message; backend injects full risk-context system prompt before first message of a session |
| GET | `/chat/{userId}/history` | Yes | Full chat session history |

## 5. Reports
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| POST | `/reports/{userId}/generate` | Yes | Trigger async PDF generation, returns `202 Accepted` |
| GET | `/reports/{reportId}/status` | Yes | Poll generation status |
| GET | `/reports/{reportId}/download` | Yes | Download finished PDF |

## 6. Admin (role = admin only, see `03-AUTH.md` §5)
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| GET | `/admin/users` | Admin | List users + latest prediction summary |
| DELETE | `/admin/users/{userId}` | Admin | Delete a full user record (cascade) |
| POST | `/admin/models/retrain` | Admin | Trigger retraining job for a given `disease_key` |

## 7. Health/System
| Method | Endpoint | Auth | Description |
|---|---|---|---|
| GET | `/health` | No | Liveness probe for Docker healthcheck |

## 8. Response Shape Conventions
- All risk-bearing responses (`/predict/*`, `/simulate`) must include a `disclaimer` string field at
  the top level — never rely on the frontend to attach it.
- `disease_risk_results` in a `/predict` response is an array (one row per active disease), not fixed
  columns — this mirrors the normalized `disease_risk_results` table in `04-DATA-MODEL.md`.
- Pagination (`/predict/{userId}/history`, `/admin/users`): `?page=1&page_size=20`, response
  includes `total`, `page`, `page_size`, `items`.
- Validation errors: FastAPI/Pydantic default `422` shape, field-level `loc`/`msg` — frontend maps
  `loc` to the matching form field.

## 9. Example: `POST /predict` response (shape, not literal values)
```json
{
  "prediction_id": 123,
  "biological_age": 34.2,
  "longevity_score": 71.5,
  "longevity_category": "Good",
  "depression_level": "Mild",
  "depression_confidence": 0.82,
  "anxiety_level": "Minimal",
  "disease_risk_results": [
    { "disease_key": "diabetes", "category": "metabolic", "risk_percent": 18.4, "risk_label": "Low" },
    { "disease_key": "stroke", "category": "cardiovascular", "risk_percent": 42.1, "risk_label": "Moderate" }
  ],
  "disclaimer": "This is an AI-estimated health risk assessment, not a medical diagnosis. Consult a qualified doctor."
}
```
